# Validation

Backend validated on 11 September 2026: **46 passing tests**, including ten conversation-history cases and nine Ollama lifecycle/routing cases. Ruff passes. The last full frontend suite has **62 passing tests**: 26 service tests, 31 rendered route/interaction tests and 5 dedicated HTTP-mode integration tests. TypeScript and the HTTP-mode production build were checked on 10 September for the memory-status UI changes; frontend code was not changed by the history or routing-format fixes. Earlier frontend lint and Python formatting checks also passed.

The invalid-plan error was reproduced live with local Gemma: it returned valid JSON containing `prompt`, `use_knowledge` and `reason`, but omitted `type` for programming, RAG and biography questions. Managed Ollama classification now enforces a schema requiring a supported route and a boolean knowledge flag. A compact prompt with examples produced valid routing responses in live checks. Three new full-task regression cases reproduce the missing-type response in unconstrained mode and verify schema enforcement, FAST dispatch, response completion, token accounting and pinned orchestration. Output structure is enforced; semantic classification quality still depends on the model and the existing control-plane validation.

A full FastAPI workflow for the exact prompt "What is programming ?" completed against the actual Windows Gemma and Mac Qwen endpoints, using an isolated temporary database and the configured 512-token text-output cap. It selected the general/FAST route, generated an answer, unloaded the Mac specialist and kept Windows Gemma resident. Total elapsed time was 132.3 seconds, including classification, loading, generation and cleanup; this is a functional check, not a performance benchmark. The user's conversation records were not modified by this check.

The history regression reproduced a failed first question being supplied to the next turn's orchestrator and specialist. Both models now receive only earlier successful exchanges, trimmed as whole pairs. Tests cover invalid-plan failures, cancelled requests, partial failed answers, successful follow-ups, explicit retries, separate chats/users, and zero/limited history budgets. Read-only inspection of the reported saved conversation confirms that its failed question is excluded by the new history selector. Its actual conversation IDs were valid; the earlier diagnosis of null IDs mistakenly read the message JSON instead of the dedicated database column. Existing saved answers are not rewritten.
